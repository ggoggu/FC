# AI 파이프라인 활용 및 토큰 최적화 가이드라인

본 가이드라인은 **FC 프로젝트(UE5.8)**에서 AI 페어 프로그래밍을 진행할 때, **최소한의 토큰 소모**로 **최고의 코드 품질과 검증 결과**를 얻기 위한 프롬프트 작성 지침입니다.

---

## 1. 핵심 원칙: "필요할 때만 원하는 수준으로 검증"

* **기본 모드 (Fast Track - 0 추가 토큰)**:
  - 단순 코드 작성, 질문 답변, 기능 구현, 리팩토링 시에는 무거운 검증 스크립트를 돌리지 않는 것이 기본 동작입니다.
  - 불필요한 빌드/로그 출력을 건너뛰어 대화 속도를 높이고 토큰을 대폭 절약합니다.

* **온디맨드 검증 (On-Demand Verification)**:
  - 검증이 필요할 때 명시적으로 원하는 검증 단계를 프롬프트에 포함합니다.
  - AI는 여러 스크립트를 개별 호출하지 않고 `Scripts/pipeline.py <mode>` 단 1회 명령으로 일괄 처리합니다.

* **GAS 적용 기준**:
  - 일반적인 게임플레이 기능은 표준 C++ 및 언리얼 엔진 컴포넌트/인터페이스로 깔끔하게 작성됩니다.
  - **GAS(Gameplay Ability System)는 사용자가 명시적으로 요구하거나(예: "GAS 기반으로..."), 어트리뷰트/어빌리티/태그 기반 이펙트 시스템을 구현할 때만 고려**하여 적용합니다.
  - `pipeline.py static`은 프로젝트 내의 리플리케이션 및 대역폭을 점검하며, 작성된 GAS 클래스가 있을 경우 GAS 매크로/콜백 규칙도 함께 스마트하게 자동 검증합니다.

---

## 2. 모듈형 파이프라인 모드와 호출 프롬프트

### 🟢 모드 1: Fast Mode (기본 모드 / 스크립트 미실행)
> **목적**: 빠른 코드 초안 작성, 알고리즘 구현, 블루프린트 연동 설명 등
```text
"Source/FC/Public/Character/FCCharacter.h에 구르기(Dodge) 기능을 위한 입력 바인딩 함수와 상태 변수를 추가해줘. (검증 스크립트는 실행하지 말고 코드만 작성해줘)"
```

---

### 🟡 모드 2: Static Audit Mode (초고속 정적 검사 / ~0.2초)
> **목적**: 리플리케이션 규칙, 대역폭 조건(`COND_OwnerOnly`), GAS 매크로 준수 여부(GAS 클래스 존재 시)를 초고속 점검
> **내부 실행**: `python Scripts/pipeline.py static`
```text
"방금 작성한 코드에 리플리케이션이나 네트워크 규칙 위반이 없는지 정적 검증(static audit)을 돌려줘."
```

---

### 🟠 모드 3: Build & Fix Mode (컴파일 검증 및 자가 교정)
> **목적**: UnrealBuildTool(UBT) 컴파일을 수행하고 컴파일 에러 발생 시 자가 수정
> **내부 실행**: `python Scripts/pipeline.py build`
```text
"새로 작성한 소스 코드가 정상 컴파일되는지 빌드 파이프라인을 실행하고, 에러가 있다면 자가 수정해줘."
```

---

### 🟣 모드 4: Combat Balance Mode (전투/TTK 시뮬레이션 / ~0.2초)
> **목적**: 무기 대미지, 공격 속도, 치명타, 방어구 관통력에 따른 유효 DPS 및 TTK 곡선 분석
> **내부 실행**: `python Scripts/pipeline.py balance`
```text
"현재 무기 아키타입들의 TTK 밸런스 시뮬레이션을 실행하고, 중갑(Heavy Armor) 대상 DPS 결과를 요약해줘."
```

---

### 🔵 모드 5: Full Release & Commit Mode (전체 파이프라인 검증 + Git 커밋)
> **목적**: 정적 검증 $\rightarrow$ 컴파일 빌드 $\rightarrow$ 자동화 테스트를 순차 완수하고 Conventional Commits 형식으로 Git 커밋 생성
> **내부 실행**: `python Scripts/pipeline.py full --auto-commit -m "..."`
```text
"기능 구현을 완료했으니, 전체 파이프라인 검증(full pipeline)을 돌리고 통과하면 'feat(character): implement character dash action' 메시지로 커밋해줘."
```

## 3. 토큰 절약을 위한 프롬프트 작성 꿀팁

1. **로그 전체 출력 요구 지양**:
   - ❌ *"빌드 로그 전부 화면에 보여줘"* $\rightarrow$ 수천 줄의 로그로 토큰 급증
   - ⭕ *"빌드 돌리고 에러 요약만 알려줘"* $\rightarrow$ 간결한 핵심 요약만 수신
2. **단일 명령어 파이프라인 지시**:
   - ❌ *"verify_gas.py 돌리고, 그 다음 audit_bandwidth.py 돌리고, 그 다음 build_harness.py 돌려줘"* (다중 툴 호출 발생)
   - ⭕ *"정적 검증 돌려줘"* 또는 *"전체 검증 파이프라인 돌려줘"* (`pipeline.py` 단일 실행)
3. **명확한 클래스 및 경로 명시**:
   - 모듈명 `FC` (`Source/FC/Public/...`, `Source/FC/Private/...`)를 명확히 지정하면 AI의 불필요한 파일 탐색 과정을 줄일 수 있습니다.
