# AI 파이프라인 활용 및 결정론적 검증 가이드라인

본 가이드라인은 **FC 프로젝트(UE 5.8)**에서 AI 에이전트와 협업할 때 **일관된 품질 게이트**와 **토큰 효율성**을 동시에 달성하기 위한 실전 명령어 및 프롬프트 지침입니다.

---

## 1. 핵심 원칙: 단일 결정론적 검증 루프 (No Optional Modes)

이전의 "Fast Track(검증 생략)" 분기는 폐기되었습니다. 모든 C++/에셋 변경은 **`AGENTS.md` §2의 단일 결정론적 루프**를 따르며, `.agents/hooks.json`과 `.git/hooks/pre-commit`이 기계적으로 이를 강제합니다.

1. **코딩 전 Ground Truth 확인**: `.uasset`(BP/WBP/Anim/DT)을 추측하지 않고 Live **`wildcard-mcp`** (`fc_toolset.FCTools`, `UMGToolSet`, `MVVMToolset`, `BlueprintTools`) 또는 오프라인 `python Scripts/pipeline.py inspect --asset <path>`로 실제 스키마 확인.
2. **C++ 수정 직후 증분 정적 게이트 (`~0.1s`)**:
   - `python Scripts/pipeline.py static --file <수정된_파일>`
   - 에이전트가 실수로 누락해도 `.agents/hooks/stop_static_gate.py` (`Stop` 훅)가 턴 종료 전에 자동 검증하여 위반 시 종료를 차단합니다.
3. **Anti-Reward-Hacking 보호**:
   - `.agents/hooks/guard_verifiers.py` (`PreToolUse` 훅)가 검증 스크립트(`Scripts/verify_*.py`, `audit_bandwidth.py`, `linter_baseline.json` 등) 수정 시 사용자 명시적 승인(`force_ask`)을 요구합니다.
   - 린터 규칙 수정 시 `python Scripts/tests/test_linters.py` 회귀 테스트로 정합성을 검증합니다.

## 2. 통합 파이프라인 모드 (`Scripts/pipeline.py` / `.\pipeline.ps1`)

| 모드 | 실행 명령어 | 용도 및 특징 |
| :--- | :--- | :--- |
| **증분 정적 검증** | `python Scripts/pipeline.py static --file <path>` | 수정 파일(`.h`/`.cpp` 페어) 즉시 검증 (`~0.1s`) |
| **전체 정적 검증** | `python Scripts/pipeline.py static` | GAS + Bandwidth + Replication 전수 검증 (`~0.5s`, Hard Constraint 전부 `ERROR`) |
| **UBT 컴파일** | `python Scripts/pipeline.py build` | UBT 빌드 + JSON 진단 + 서킷 브레이커 (동일 에러 2회 / 연속 실패 3회 시 Reflexion) |
| **자동화 테스트** | `python Scripts/pipeline.py test` | Headless `FC.*` Automation Spec 실행 (0-Test 실행 시 `FAILED` 처리) |
| **네트워크 열화 테스트** | `python Scripts/pipeline.py net` | `/Game/Level/Lv_BattleTest` 대상 lag/loss/dup 실행 (맵 미존재·타임아웃·0-Test 시 `FAIL`) |
| **전투 밸런스** | `python Scripts/pipeline.py balance` | 무기/카드 아키타입별 TTK/DPS 시뮬레이션 |
| **에셋 스키마 조회** | `python Scripts/pipeline.py inspect --asset <path>` | 오프라인 `.uasset` 메타데이터 추출 (`mtime_ns` 캐시, `--no-cache` / `--deep` 지원) |
| **적대적 감사 준비** | `python Scripts/pipeline.py audit` | C++ diff + 전체 정적 검증(GAS 포함) 패키징 → `/interrogate` 서브에이전트 전달 |
| **전체 릴리스 루프** | `python Scripts/pipeline.py full --auto-commit -m "..."` | `static -> build -> test -> git commit` Fail-Fast 순차 실행 |
| **하네스 자가 테스트** | `python Scripts/tests/test_linters.py` | 린터·런너·서킷 브레이커·훅 17개 단위 회귀 테스트 (`~0.12s`) |

## 3. 실전 프롬프트 작성 팁

1. **요약 중심 요청**: `"빌드 로그 전체 출력"` 대신 `"빌드 실행 후 에러 요약과 수정 방안만 알려줘"`로 토큰 절감.
2. **Proof-Carrying 리뷰 요청**: 기능 완료 후 `"/interrogate로 방금 변경분 감사해줘"`를 호출하면 `pipeline.py audit` 및 빌드/테스트 증거를 포함해 읽기 전용 `adversarial-auditor`가 5대 차원 + 6대 보안 불변량을 검증합니다.
3. **레거시 부채 확인**: 기존 동결된 `ConstructorHelpers` 19건을 전수 확인하려면 `python Scripts/verify_replication.py --ignore-baseline --pretty`를 실행합니다.
